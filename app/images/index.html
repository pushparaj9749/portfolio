How it worksand why it can't see you

1 · Nothing is uploaded

Decoding and encoding happen inside a Web Worker using OffscreenCanvas. There is no API on the other end — this file is static. The counter in the header is a real network audit: it wraps fetch, XMLHttpRequest and sendBeacon and shows every off-origin request. It should stay 0.

2 · Re-encoding is what strips metadata

Drawing a decoded bitmap to a fresh canvas keeps pixels and discards everything else: EXIF camera data, GPS coordinates, colour profiles, thumbnails, software tags. We show you which markers were found in the original so you can check our work.

3 · Parallel by default

A pool of workers sized to your CPU chews through a batch at once, so 60 phone photos take seconds, not minutes. No browser support? The identical pipeline falls back to the main thread instead of failing.

4 · Bulk output that behaves

Downloads are generated as blob: URLs — no round trip. "Download all" builds a standard .zip by hand (STORE entries + CRC-32), so you get one file with sane names and no 60 download prompts.

Is my phone or camera data really in there?

Usually yes. A photo taken on a phone commonly carries make/model, exposure, lens, timestamp, device orientation, a thumbnail, and often latitude and longitude. Anyone who gets the file can read it with a hex editor. Run the strip option before you post anything personal.

Will I lose quality?

Any lossy encoder trades bytes for detail, so yes — a little, by design. Quality 82–88 is visually indistinguishable from the original for photos on screens. PNG output is lossless, and "keep original size" only changes the container and metadata.

Why does an AVIF/PNG come out bigger than my JPEG?

Small, noisy or already-optimised images often gain nothing from another lossy pass, and PNG is a poor fit for photographs. Turn on "skip files that would end up bigger" and Bench keeps the original bytes for those entries.

Why is it faster than the other tools?

Because there's no upload. A 12 MB photo over a mobile connection can cost more time in transit than in processing; here the only cost is your CPU, split across every core it can find.
