Why it is built like thisand how to check me

No server to trust

There is no API, no analytics and no CDN. The page is 0 dependencies, so the whole thing is measurable: open devtools, sort network by domain, and you should see exactly one — the one serving this page. The badge in the header counts off-origin requests live by wrapping fetch, XMLHttpRequest and sendBeacon. It should stay 0.

The maths is testable, not vibes

Every tool's logic is a plain ES module of pure functions — sha256(), diffDates(), parseCsv(), contrastRatio() — imported by a Node test-suite that checks them against reference implementations: the Web Crypto API, Node's crypto, RFC 4180, the WCAG formula. When a test disagrees with the page, the page gets fixed.

Yours, then gone

Pasted text lives in memory and, where it helps, in this browser's local storage so a refresh does not eat your work. Close the tab and it is unreachable. There is no account to delete because there was never an account.

Installable, and it works on a plane

A service worker caches the shell, so after the first visit every tool opens with the wifi off. Install it from your browser's address bar and it behaves like an app — one you can keep in a folder of bookmarks for the next ten years.

Is “no upload” actually true, or marketing?

There is no code path that could upload. No server URL exists to post to, and the page loads no third-party script. If you want to verify it: devtools → Network → add a filter for -is:from-this-origin. Anything you type stays in the DOM. On the images tool, files are read with createImageBitmap() and re-encoded with canvas.convertToBlob(), both local APIs.

Why not just use an online converter?

Because most of them do the same work in the browser anyway, and then hand you a billboard, a cookie wall and an upload step that quietly puts your passport scan on someone's disk. Bench is slower to find and faster to use: no upload queue, no size cap, no “create an account to download”.

My hashes look right — can I trust a web page with security work?

For checksums and lookups, yes: SHA-256 here is a plain implementation of FIPS 180-4 and matches crypto.subtle and sha256sum on every input we test. For secrets, don't paste a private key into any website, including one that cannot read it. Use openssl or shasum for anything that would hurt to leak; use this page to check a download or to find the right UUID format.

Does it work in a private window, or offline?

Private windows: yes, though the browser may refuse local storage — Bench degrades to “nothing is remembered” instead of failing. Offline: yes after one visit, because the shell is precached. On file:// the pure-JS tools keep working; the image tool's worker may not, since workers need an http origin, so we tell you and fall back to the main thread.

Can I run my own copy?

Fork it, drop the app/ folder on any static host — GitHub Pages, Netlify, an S3 bucket, a folder on a NAS. There is no build step, no lockfile and nothing to configure. If you do host it, put it behind https so the platform crypto API and the service worker both work.
